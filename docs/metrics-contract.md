# Контракт `dashboard/metrics.json` (v1)

Спільна домовленість між скілами (`stage-1-supplax`, `automation-portfolio-sync`) і дашбордом (`giga-brdg/automation-system`). Будь-яка зміна формату робиться спершу тут, потім у скілах і парсері.

## Навіщо
Числа «до / ціль / факт» і спосіб перевірки зараз губляться: `dashboard/ROI.md` передає лише текст і перше слово Measured/Estimated. `metrics.json` передає їх структуровано, а людське пояснення лишається в `docs/roi_explained.md`.

## Джерело правди
- Розрахунки автоматизатора в `docs/roi_explained.md`, розділ «## Метрики».
- `dashboard/metrics.json` генерується з нього скілом. Руками файл не редагують.
- Якщо цифр немає, їх не вигадують. Скіл питає, а якщо відповіді немає, записує відкрите питання.

## Формат

```json
{
  "version": 1,
  "launched_at": "2026-07-22",
  "metrics": [ <Metric>, ... ],
  "open_questions": [ <OpenQuestion>, ... ]
}
```

`launched_at`: дата запуску в прод, `YYYY-MM-DD` або `null`, якщо ще не запущено.

### Metric
| Поле | Обов'язкове | Значення |
|---|---|---|
| `id` | так | kebab-case, стабільний і ніколи не змінюється |
| `name` | так | людська назва українською |
| `type` | так | `time`, `revenue`, `cost`, `quality`, `conversion`, `other` (A/B/C/D Оксани: revenue=A, cost=B, time=C, quality=D) |
| `unit` | так | одиниця: «год/міс», «%», «лідів/тиждень», «$/міс» |
| `direction` | так | `down` (менше краще) або `up` |
| `primary` | так | `true` рівно в однієї метрики |
| `baseline` | так, можна `null` | `{value, period, source, kind}`; `kind`: `measured` або `estimate` |
| `target` | так, можна `null` | `{value, why}`; `why` пояснює, звідки ціль (бриф, керівник, розрахунок) |
| `method` | так | як перевіряємо після запуску: що з чим порівнюємо, на якому періоді, хто міряє |
| `check_every_days` | так | як часто міряти, ціле число |
| `measurements` | так, може бути `[]` | лише дописується, див. нижче |
| `money` | ні | `null` або `{rate_usd_per_unit, realization, realization_why}`. Для `time`: ставка $/год (8 спеціаліст, 15 менеджер) і коефіцієнт реалізації Оксани (0.9 не наймаємо, 1.0 скорочення, 0.5 переключення на продажі, 0.3 лише розвантаження) |

`period`: `YYYY-MM-DD..YYYY-MM-DD` або текст, якщо точного немає (тоді `kind` = `estimate`).

### Measurement
`{date, period, value, source, kind, note}`, де `date` — коли зміряно, `period` — за який період, `kind` — `measured` або `estimate`.

Правило append-only: записи з попередньої версії файлу не змінюються й не видаляються. Помилкову цифру виправляють новим записом з `note`: «виправлення заміру від DD.MM: причина».

### OpenQuestion
`{metric_id, field, question, ask_whom, since}`
- `metric_id`: id метрики або `null`, якщо питання загальне.
- `field`: назва поля, наприклад `baseline` чи `target`.
- `ask_whom`: `automator`, `department_lead`, `crm_query`, `manual_measurement` або ім'я людини.
- `since`: дата, коли питання з'явилось.

## Обов'язкові значення і що робити, якщо їх немає
Скіл перевіряє кожну метрику. Для кожного поля, яке порожнє або `null`, але має бути заповнене, він **питає автоматизатора** через `AskUserQuestion` (до 4 питань за раз). Варіанти відповіді:
1. дати значення (і джерело);
2. «Не знаю, хто знає: ...» → створюється OpenQuestion з `ask_whom`;
3. «Неможливо зміряти, бо ...» → поле лишається `null`, причина пишеться в `roi_explained.md` у Caveats.

Що вимагає відповіді:
- Метрика без `baseline` після запуску. До запуску baseline теж треба, бо Оксана: «без заміру до не стартуємо».
- Метрика без `target`.
- Метрика без `method` або `check_every_days`.
- `money` для `time` без `realization_why`.
- Прострочений замір: `launched_at + check_every_days`, або останній замір + `check_every_days`, раніше за сьогодні. Скіл пропонує додати замір.

Скіл ніколи не підставляє правдоподібне число замість відповіді. Оцінку автоматизатора можна записати лише з `kind: "estimate"` і з джерелом («оцінка автоматизатора: 15 хв × 40 разів, слова керівника»).

## Що рахує дашборд (не скіл)
- Статус метрики:
  - «Немає даних»: немає baseline і замірів;
  - «Очікуємо»: є baseline, замірів після запуску ще немає;
  - «Виміряно»: є хоч один `measured` замір після `launched_at`;
  - «Підтверджено»: Оксана підтвердила в дашборді конкретний sha.
- Результат: останній замір проти baseline з урахуванням `direction`.
- Гроші: тільки якщо є `money`; різниця × ставка × realization; оцінку й факт рахує окремо.
- Множники стратегічності й тиражованості на сторінці цінності не використовуються.
